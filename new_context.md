General style principles established

1. Controlled density, not minimalism.
    The goal is not to dilute; it is to preserve achievements while removing noise.
2. Each section has a job.
    * Headline: current identity.
    * About: arc and spine.
    * Experience: professional proof.
    * Projects: artifact-backed technical work.
    * Education: institution + academic distinction.
    * Awards: external recognitions.
    * Certifications/Test Scores: mostly removed.
    * Volunteering: communication and campus analytics signal.
3. Say each thing once.
    Thesis/paper can appear in multiple sections, but each section should carry a different slice:
    * Headline: no paper.
    * About: one sentence of signal.
    * Education: thesis grade + one-line topic.
    * Experience: one-line thesis/research role if applicable.
    * Projects: technical description + repo/site.
    * Publications: metadata only.
    * Featured: link/artifact only.
4. Do not explain prestige.
    State ETH, IBM Research Zürich, IIT Bombay, SIGMOD, VLDB, AB InBev. Do not say why they are prestigious.
5. Avoid wrong-level signals.
    Remove or hide certifications/test scores that make the user look like a student applicant rather than a research-oriented software engineer.
6. Keep artifacts only if professional.
    Best Intern Award = keep. Brewery Visit = remove. Clean award certificates/report pages = keep. Random scrapbook thumbnails = remove.
7. Use technical nouns, but avoid tool dumping.
    Keep key methods inline when they define the work: Gurobi, PuLP, Prophet, SARIMAX, XGBoost, SVD/NMF, BERTopic, Sentence Transformers, GNN, Spark, PrestoDB. Move generic tools to Skills.
8. Be honest about status.
    * “Accepted” only for accepted work.
    * “Under review” only if true.
    * “Submitted” if safer.
    * Do not imply thesis grade is degree grade.
    * Do not imply course projects are papers.
